# AutoCodeRover: Autonomous Program Improvement

Review of version `2404.05427v3` • 19 November 2026 • 13 pages. [arXiv record](https://arxiv.org/abs/2404.05427v3) · [Metadata and license](../../raw/metadata/2404.05427.metadata.json) · [Paper record](../../sources/arxiv-2404.05427.md)

## Section review

- **1–3. Problem, related work and example.** The system takes an issue and an existing codebase and produces a patch. Related work covers automatic repair, patch evaluation and agents that operate on repositories. A Django example traces a clue in an issue to the relevant code and compares the generated patch with a developer’s fix (Figures 1–3). [PDF, p. 1](https://arxiv.org/pdf/2404.05427v3#page=1) [PDF, p. 2](https://arxiv.org/pdf/2404.05427v3#page=2) [PDF, p. 3](https://arxiv.org/pdf/2404.05427v3#page=3) [PDF, p. 4](https://arxiv.org/pdf/2404.05427v3#page=4)
- **4. Method, Table 1 and Figures 2–5.** Seven search operations use classes, methods, files and code snippets. The agent progressively expands the context and narrows down the fault location. Optional spectrum-based fault localization (SBFL) uses test execution to suggest additional methods. A second stage proposes edits at the selected location and retries if the patch is malformed or fails to apply. [PDF, p. 4](https://arxiv.org/pdf/2404.05427v3#page=4) [PDF, p. 5](https://arxiv.org/pdf/2404.05427v3#page=5) [PDF, p. 6](https://arxiv.org/pdf/2404.05427v3#page=6) [PDF, p. 7](https://arxiv.org/pdf/2404.05427v3#page=7)
- **5–6. Configuration and RQ1.** The evaluation covered 2,294 issues, including the Lite (300) and Devin (570) subsets. GPT-4 used temperature 0.2. On Lite, Table 2 reports 57 tasks solved in one run and 78 across three runs, compared with 54 for SWE-agent. One attempt averaged $0.43 and 195 seconds per task, while three averaged $1.30 and 520 seconds. Figures 6–8 show overlap, cost and the token distribution. Manual review found a semantically correct fix on at least one of the three attempts for 51 of the 78 Lite tasks that passed. [PDF, p. 7](https://arxiv.org/pdf/2404.05427v3#page=7) [PDF, p. 8](https://arxiv.org/pdf/2404.05427v3#page=8) [PDF, p. 9](https://arxiv.org/pdf/2404.05427v3#page=9)
- **6.2–6.3, Figures 9–10.** Adding SBFL fault localization and validating with the full test suite increased the number of Lite tasks solved from 57 to 66. Across 300 tasks, 29.3% had an incorrect patch in the correct methods. Another 20% targeted the wrong location within the correct file. These categories describe the best attempt. - **7-9, data availability and bibliography.** The discussion considers improved fault localization and human intervention. Figure 11 records the leaderboard on July 12, 2024. A partial fix can pass the tests, and repeated LLM calls can yield different results. The authors link to a repository containing code, session histories, patches and scripts. The PDF ends with the references and has no separate appendix. ## Independent verification

In a public repository, revision `585d3e63`, the three lists `resolved` from `acr-run-{1,2,3}/new_eval_results/report.json` have, respectively, **54, 57 and 57** elements, and their union contains **78**. This matches pass@3 in Table 2, although the individual runs differ. For the full benchmark, a separate row of the same table pairs **17,96%** from **422/2294**. The ratio is **18,40%** after rounding. A rate of 17.96% would correspond to about 412 tasks. The row alone does not establish which figure is correct.
