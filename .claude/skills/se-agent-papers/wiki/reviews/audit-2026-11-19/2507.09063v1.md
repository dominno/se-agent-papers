# SetupBench: Assessing Software Engineering Agents' Ability to Bootstrap Development Environments

Audit opened on 19 November 2026 for version `2507.09063v1`, 18 pages. [Paper record](../../sources/arxiv-2507.09063.md) · [arXiv record](https://arxiv.org/abs/2507.09063v1) · [Authors, license and checksum](../../raw/metadata/2507.09063.metadata.json)

## Sections and Appendices

- Sections 1–2. The authors isolate the project setup stage in a clean container. Table 1 includes 54 repository tasks, 16 dependency conflicts, 15 database configurations, and eight services. Although the table lists pip/Poetry, all 16 final dependency conflicts came from npm (9) or Bundler (7). A command executed in a fresh shell checks whether setup succeeded. - Sections 3.1–3.3 and Table 2. Overall success ranged from 34.4% to 62.4% in five OpenHands configurations. Missing developer tools, changes based on invented requirements, and settings lost in a new shell account for some failures. The behavioral analysis uses the same agent with different models. [PDF, p. 4](https://arxiv.org/pdf/2507.09063v1#page=4) [PDF, p. 5](https://arxiv.org/pdf/2507.09063v1#page=5)
- Sections 3.4–4, Tables 3–4. The authors converted human operations on ten repositories into equivalent agent actions. They excluded activities such as initialization and process monitoring. Excess steps involved repeated reads, irrelevant files and actions that diverged from the instructions. Section 4 suggests further tasks that depend on successful installation. [PDF, p. 6](https://arxiv.org/pdf/2507.09063v1#page=6) [PDF, p. 7](https://arxiv.org/pdf/2507.09063v1#page=7) [PDF, p. 8](https://arxiv.org/pdf/2507.09063v1#page=8)
- Sections 5–7. Manual selection, small groups, broad permissions, and open network access limit generalization. Comparisons with other benchmarks define the scope of the problem. A proposed extension combines environment setup with subsequent task completion. [PDF, p. 8](https://arxiv.org/pdf/2507.09063v1#page=8) [PDF, p. 9](https://arxiv.org/pdf/2507.09063v1#page=9)
- Appendices A–E. Appendix A shows a task record. B describes how the instructions and validator are generated. C covers extracting and reproducing conflicts from pinned revisions. D gives three MySQL configurations and E a Gunicorn task. The observable success criterion can cover only part of a requirement. In E, a response through a socket verifies that the service runs, but the test does not check whether it restarts after failure. ## Independent check

For Claude 4, Table 2 gives 6/8 services, 7/15 databases, 31/54 repositories, and 14/16 dependencies, for a total of **58/93 = 62,37%**. Tables 3–4 require summing positive overruns separately by repository. For GPT-4o this gives 76/193 = 39.38%. The difference between the totals is only 193 − 124 = 69 because shorter trajectories do not offset overruns on other tasks. For Claude 3.5 the same calculation yields 71/186 = 38.17%. Reproducing the arithmetic does not establish that the human trajectory defined by the authors is optimal.
