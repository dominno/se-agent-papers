# Agent Memory: Characterization and System Implications of Stateful Long-Horizon Workloads

## Study content and empirical evidence

- Sections 1–2 and Table 1. The common workflow covers ingestion, construction, storage, retrieval, context assembly, response generation and memory maintenance. The ten configurations include a full-context baseline and nine external systems. Write mechanisms range from indexing to consolidation and model-selected tool calls. [PDF, p. 1](https://arxiv.org/pdf/2606.06448v2#page=1) [PDF, p. 2](https://arxiv.org/pdf/2606.06448v2#page=2) [PDF, p. 3](https://arxiv.org/pdf/2606.06448v2#page=3) [PDF, p. 4](https://arxiv.org/pdf/2606.06448v2#page=4)
- Section 3 and Table 2. MemoryAgentBench profiling uses five histories of about 360,000 tokens each, with 60 questions per history. A separate experiment covers 20 multisession physical tasks from MemoryArena. Local measurements combine API telemetry with H100 hardware counters. Shared models and record retrieval limits aid comparison, although prompts, chunking and tool limits vary by implementation. [PDF, p. 4](https://arxiv.org/pdf/2606.06448v2#page=4) [PDF, p. 5](https://arxiv.org/pdf/2606.06448v2#page=5) [PDF, p. 9](https://arxiv.org/pdf/2606.06448v2#page=9)
- Sections 4.1–4.4, Figures 2–6 and Table 3. Answer latency excludes memory construction. Across 300 questions with Qwen3-32B, BM25 achieved 47.0% and GraphRAG 46.0%, consuming 582 and 2,082 kJ of GPU energy, respectively. Input processing and embeddings dominate construction. At ten tenants throughput increased 9.6× for Mem0 and 1.4× for HippoRAG v2. With the answering model fixed, MIRIX failed with a 1.7B construction model. - Sections 4.5–4.8, Figures 7–11 and Section 5. Macro-averaging across datasets favors lexical retrieval on recall questions. With five-second intervals, slow writes cause waiting under synchronous operation or stale reads under asynchronous operation. The authors also study single-user memory up to one million tokens, separating pre-response latency from tail latency. The p95/p50 ratio is 1.3 for BM25 and 5.9 for GraphRAG. The measurements exclude multinode and multimodal stores. Section 7 of the supplement describes TP and sharing as configurations outside the reported results, although Section 4.3 of the main text gives results for both. ## Independent verification

From Table 3, BM25 uses 582,000/(300 × 0.47) ≈ 4,128 J per correct answer, versus 15,084 J for GraphRAG. The narrative’s 26.5× ratio compares Letta with BM25. The full range in the energy column is larger: 15,429/495 ≈ **31,17×** between Letta and embedRAG. Extrapolating deployment costs requires identifying the baseline for each comparison.
