# SlopCodeBench: Benchmarking How Coding Agents Degrade Over Long-Horizon Iterative Tasks

## Sections and Appendices

- Sections 1–2. For each of 36 problems, a new requirement is revealed only after the preceding stage. The agent extends its own codebase. The study distinguishes success on the current stage, preservation of earlier features, and core tests. Erosion concerns how complexity becomes concentrated. Redundancy includes duplication of code. - Section 3, Tables 1–3 and Figures 2–5. With a fixed denominator of 196 checkpoints, a missing stage counts as unsolved. Cost and quality cover only stages performed. The highest strict score was 14.8%. No system solved a whole problem end to end. Erosion increased in 77% of trajectories and redundancy in 75.5%. The human comparison uses 473 Python projects and 13,667 commits. An instruction change can improve structural metrics while strict correctness falls. ## Independent check

The means in Table 2 give 0.44/0.19 ≈ **2,32×** redundancy and 0.68/0.34 = **2,00×** erosion relative to the panel. For some trajectory comparisons the agents and humans worked on different problems, so the result cannot identify the cause of the difference.
