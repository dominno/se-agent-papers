# Can Large Language Models Resolve Real Java Merge Conflicts? An Evaluation with a Calibrated LLM-as-Judge

Review of version `2607.27674v1` • 19 November 2026 • 18 pages. [arXiv record](https://arxiv.org/abs/2607.27674v1) · [Metadata and license](../../raw/metadata/2607.27674.metadata.json) · [Paper record](../../sources/arxiv-2607.27674.md)

## Section review

- **1–2.** A real conflict requires choosing between incompatible changes. An apparent conflict can be resolved by combining compatible edits. ConflictBench supplies developer decisions and ratings for traditional tools’ outputs. The paper evaluates two models that resolve conflicts and examines the reliability of a separate evaluator model. - **3. Procedure, Figures 1–4.** The resolution model sees the common ancestor, both branches and the surrounding code. After inserting a candidate, validation checks conflict markers, parsing and duplicate declarations. Generation can be retried for up to four rounds. The developer’s resolution is revealed only during evaluation. Calibration counts scenario–tool pairs. Agent performance counts scenarios. Of 180 scenarios, 93 were reproducible and 67 were compared with the developer’s decision, including 49 real conflicts. - **4. Calibration, Table 1.** In 292 human-labeled pairs the counts were TP 117, FP 0, TN 111 and FN 64, with the G-Eval judge threshold set to 0.5. This validation used candidates from traditional tools. LLM outputs did not receive a complete independent human labeling, which limits transfer of the precision estimate. - **5. Results, Tables 2–4.** Among gradable outputs for real conflicts, 27/49 and 29/47 matched the developer’s resolution. Using 49 as the common denominator changes the second rate from 61.7% to 59.2%. AutoMerge achieves 18/49 (36.7%). Among the outputs it actually produced, JDime achieves 17/31 (54.8%). Deterministic validation found 92/96 structurally valid outputs for real conflicts and 35/36 for apparent conflicts. The language-model judge accepted four of five structurally invalid candidates. - **6–7, Table 5.** Across six case studies, the method outperforms a simple heuristic twice, while simple branch selection wins once. The remaining cases show disagreement between metrics on RxJava, a missed case where the reference match was ambiguous, and a correct abstention. How often each tool offers an answer affects the comparison. ## Independent verification

The Table 1 confusion matrix yields 117/(117 + 64) = **64.64% recall** and (117 + 111)/292 = **78.08% accuracy**. Precision in this sample is 100%. Observing zero false acceptances does not guarantee that precision in another population. With a common denominator in Table 3, the gains over AutoMerge are 9/49 and 11/49, or **18.37 and 22.45 percentage points** Two ungradable Gemini outputs explain the difference between the denominators of 47 and 49.
