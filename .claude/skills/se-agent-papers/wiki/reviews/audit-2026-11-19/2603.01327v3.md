# SWE-Adept: An LLM-Based Agentic Framework for Deep Codebase Analysis and Structured Issue Resolution

## Section review

- §§1–2 and Figures 1–2. The task separates identifying a repository location from repairing it. Related work compares software engineering agents with memory mechanisms. The figures illustrate the separate processes and relationships between hypotheses and stored project states. [PDF, p. 1](https://arxiv.org/pdf/2603.01327v3#page=1) [PDF, p. 2](https://arxiv.org/pdf/2603.01327v3#page=2) [PDF, p. 3](https://arxiv.org/pdf/2603.01327v3#page=3) [PDF, p. 4](https://arxiv.org/pdf/2603.01327v3#page=4)
- Section 3. Tree-sitter produces the syntax tree used to build the index. The agent examines short snippets, filters the candidates, then reranks them using their full contents. The repair agent can consider several hypotheses and restore a previous state. Hypothesis and step names refer to checkpoints in shared memory. [PDF, p. 4](https://arxiv.org/pdf/2603.01327v3#page=4) [PDF, p. 5](https://arxiv.org/pdf/2603.01327v3#page=5) [PDF, p. 6](https://arxiv.org/pdf/2603.01327v3#page=6)
- §4 and Tables 1–3. With GPT-5.2 on Lite, the correct function was in the top five in 70.8% of cases, compared with 64.6% for LocAgent, a difference of 6.2 percentage points. On the 200-instance Pro set, the repair rate was 37.8% versus 33.5% for OrcaLoca, a difference of 4.3 points. The two comparisons use different samples and metrics and both give absolute differences. Table 3 divides Pro into 60 Python tasks, 60 JavaScript, 60 Go and 20 TypeScript. For Claude, the highest repair score is 58.3% in Python, the lowest 32.5% in Go. [PDF, p. 7](https://arxiv.org/pdf/2603.01327v3#page=7) [PDF, p. 8](https://arxiv.org/pdf/2603.01327v3#page=8) [PDF, p. 12](https://arxiv.org/pdf/2603.01327v3#page=12) [PDF, p. 13](https://arxiv.org/pdf/2603.01327v3#page=13)
- Section 5, Figures 4–5 and Tables 4–6. On Lite with Claude, 56.1% of search calls navigate to a child entity. The relationship between depth and performance is observational. Replacing the repair module lowers the Pro score from 45.0% to 41.5%. Replacing localization lowers it to 43.3%. Short previews reduce the search token count. Replacing memory and wrapped operations with raw Git yields 41.5%. - Section 6, limitations, and ethics. The main evaluation covers two commercial models. Long runs are expensive, and patches require human review. The references precede the appendices. [PDF, p. 8](https://arxiv.org/pdf/2603.01327v3#page=8) [PDF, p. 9](https://arxiv.org/pdf/2603.01327v3#page=9) [PDF, p. 11](https://arxiv.org/pdf/2603.01327v3#page=11) [PDF, p. 12](https://arxiv.org/pdf/2603.01327v3#page=12)
- Appendices A–B. Lite contains 300 cases, of which 274 support function-level evaluation. The authors averaged two runs at temperature 0.1. Tables 7–8 add comparisons with Claude Code, mini-SWE-Agent, GLM and Qwen. For Qwen3.5-27B the Pro repair rate is 38.3%, versus 33.8% for SWE-agent. Tables 9–11 and Figures 6–7 give the tools, roles and instructions. Figure 3 manually classifies errors where the two methods differ. Its distribution covers that selected subset of failures. The implementation repository is linked on page 1.
