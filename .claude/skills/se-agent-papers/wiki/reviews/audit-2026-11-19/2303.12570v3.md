# RepoCoder: Repository-Level Code Completion Through Iterative Retrieval and Generation

Independent audit on 19 November 2026 • 2303.12570v3 · [Paper record](../../sources/arxiv-2303.12570.md)

## Section-by-section review

- **1–2, Figures 1–3.** RepoCoder retrieves similar code windows from the repository. The first query uses the prefix of the unfinished file. The next combines the end of the observed context with the start of the predicted continuation. Paths and examples are included in the prompt. The model and retriever parameters stay fixed. [PDF, p. 1](https://arxiv.org/pdf/2303.12570v3#page=1) [PDF, p. 2](https://arxiv.org/pdf/2303.12570v3#page=2) [PDF, p. 3](https://arxiv.org/pdf/2303.12570v3#page=3) [PDF, p. 4](https://arxiv.org/pdf/2303.12570v3#page=4)
- **3–4, Table 1.** RepoEval contains 1,600 line completions and 1,600 API-call completions from eight repositories, plus 373 function bodies from six other repositories. The authors selected mainly Python repositories with tests created after the start of 2022. They compared single-file context, single and repeated retrieval and a reference query containing part of the expected answer. The main experiment uses Jaccard similarity. Exact match requires identical text, while function bodies are evaluated using repository tests. [PDF, p. 4](https://arxiv.org/pdf/2303.12570v3#page=4) [PDF, p. 5](https://arxiv.org/pdf/2303.12570v3#page=5) [PDF, p. 6](https://arxiv.org/pdf/2303.12570v3#page=6)
- **5, Tables 2–3.** The second GPT-3.5-Turbo iteration achieves 56.81% exact match on line completion, compared with 55.31% for the first and 40.56% with single-file context. For API calls, the corresponding figures are 49.19%, 47.69% and 34.06%. For function bodies, test pass rates are 42.63%, 38.34% and 23.32%. Function-level performance declines from the second to the third iteration. [PDF, p. 6](https://arxiv.org/pdf/2303.12570v3#page=6)
- **6, Tables 4–5.** Among cases where the repository contained an example of the correct API call, GPT-3.5-Turbo’s retrieval rate for such an example rose from 86.04% to 90.34% after the second iteration. Table 5 covers only cases in which retrieval corrected a wrong In-File output. Code-location categories can overlap. Restricting retrieval to selected locations lowered performance. [PDF, p. 7](https://arxiv.org/pdf/2303.12570v3#page=7) [PDF, p. 8](https://arxiv.org/pdf/2303.12570v3#page=8)
- **7–8 and limitations.** The authors place the work in the context of code completion and combined retrieval and generation. The cost of further rounds, sparse code repetition and the need to choose a stopping point limit use in an interactive editor. [PDF, p. 8](https://arxiv.org/pdf/2303.12570v3#page=8) [PDF, p. 9](https://arxiv.org/pdf/2303.12570v3#page=9)
- **Appendices A–C, Tables 6–7 and Figure 4.** The repository list gives licenses, sizes, creation dates and status as of January 2023. With the UniXcoder dense retriever, GPT-3.5’s second round achieves 49.13% EM on API calls, close to 49.19% for the main configuration. The number of duplicate lines in a repository does not uniquely determine the gain. [PDF, p. 6](https://arxiv.org/pdf/2303.12570v3#page=6) [PDF, p. 11](https://arxiv.org/pdf/2303.12570v3#page=11) [PDF, p. 12](https://arxiv.org/pdf/2303.12570v3#page=12) [PDF, p. 13](https://arxiv.org/pdf/2303.12570v3#page=13)
- **Appendices D–E, Table 8 and Figure 5.** Later iterations gain some correct answers and lose others. Strict exact match excludes functionally correct alternatives. In Appendix E, three commercial tools gave incorrect results on one selected API call. This is a single-task illustration. [PDF, p. 13](https://arxiv.org/pdf/2303.12570v3#page=13) [PDF, p. 14](https://arxiv.org/pdf/2303.12570v3#page=14)

## Independent verification

For the second GPT-3.5 iteration on API calls, Table 8 gives 787/1,600 = 49.1875%, consistent with 49.19% in Table 2b. Third- and fourth-round counts give 794/1,600 = 49.625% and 790/1,600 = 49.375%, while Table 2b gives 49.44% and 49.56%. The PDF does not establish which series is correct. The card uses the second-round result, which agrees in both places.
