# Using Process Mining to Generate AI Agents from Software Engineering Process Records

Audit opened on 19 November 2026 for version `2607.04948v1`, 18 pages. [Paper record](../../sources/arxiv-2607.04948.md) · [arXiv record](https://arxiv.org/abs/2607.04948v1) · [Authors, license and checksum](../../raw/metadata/2607.04948.metadata.json)

## Sections and evidence

- Sections 1–2 and Table 1.1. An object-centric log links events to issues, commits and people. An event may involve multiple objects. The authors compare modeling a project’s actual process with assigning roles to agent teams from the top down. [PDF, p. 1](https://arxiv.org/pdf/2607.04948v1#page=1) [PDF, p. 2](https://arxiv.org/pdf/2607.04948v1#page=2) [PDF, p. 3](https://arxiv.org/pdf/2607.04948v1#page=3) [PDF, p. 4](https://arxiv.org/pdf/2607.04948v1#page=4)
- Section 3 and Figure 1.1. GitHub data are used to construct the log. Conventional Commits messages identify some tasks and rules assign roles. Partitioning the log produces directly-follows graphs, process models, DECLARE constraints and textual specifications. These are used to generate LangGraph applications. [PDF, p. 5](https://arxiv.org/pdf/2607.04948v1#page=5) [PDF, p. 6](https://arxiv.org/pdf/2607.04948v1#page=6) [PDF, p. 7](https://arxiv.org/pdf/2607.04948v1#page=7) [PDF, p. 8](https://arxiv.org/pdf/2607.04948v1#page=8)
- Sections 4.1–4.2 and Table 1.2. The researchers identified eight roles in eight years of Commitizen history and implemented five specialized agents. The rules for assessing 20 commits in three task classes were not statistically optimized. Three functional tests exercise example routing paths. [PDF, p. 8](https://arxiv.org/pdf/2607.04948v1#page=8) [PDF, p. 9](https://arxiv.org/pdf/2607.04948v1#page=9) [PDF, p. 10](https://arxiv.org/pdf/2607.04948v1#page=10) [PDF, p. 11](https://arxiv.org/pdf/2607.04948v1#page=11)
- Sections 4.3–4.4 and Figure 1.2. Ten participants rated descriptions of four roles in randomized order. They assessed five criteria and answered three open-ended questions. On a 1–5 scale, median ratings were 4 for operational clarity, 3 for accountability for errors and 2 for clarity of autonomy boundaries. For the documentation writer, the median for autonomy boundaries was 1.5. Participants also identified the risk of a bottleneck at the reviewer. ## Independent check of the paper record

1721/2765 = **62,24%** commits could be linked to a task. After enrichment, the object count was 4813 + 1721 = **6534** agrees with Table 1.2. Summing the event counts by role yields **22 196**, whereas the full log contains 21,488 events. An event is included in a role-specific log whenever someone with that role participates, so role-specific subsets can overlap. Figure 1.2 concerns the perceived clarity of the written specifications. The survey did not measure correctness of execution.
