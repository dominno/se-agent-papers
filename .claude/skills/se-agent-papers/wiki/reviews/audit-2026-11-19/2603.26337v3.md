# A Benchmark for Evaluating Repository-Level Code Agents with Intermediate Reasoning on Feature Addition Task

Independent audit on 19 November 2026 • 2603.26337v3 · [Paper record](../../sources/arxiv-2603.26337.md)

Version 3 is titled *RACE-Bench: A Reasoning-Augmented Benchmark for Repository-Level Code Agents on Feature Addition*. The historical index preserves an earlier title. [PDF, p. 1](https://arxiv.org/pdf/2603.26337v3#page=1)

## Section-by-section review

- **1 and 2.1, Figure 1.** The unit of evaluation is a feature addition in a Python repository. The agent receives a user request and fail-to-pass (FTP) tests, which pass only after the feature is implemented. Pass-to-pass (PTP) regression tests remain hidden. The accepted patch supplies the reference representation of the goal, concepts, files, tasks, and steps. [PDF, p. 1](https://arxiv.org/pdf/2603.26337v3#page=1) [PDF, p. 2](https://arxiv.org/pdf/2603.26337v3#page=2) [PDF, p. 3](https://arxiv.org/pdf/2603.26337v3#page=3) [PDF, p. 5](https://arxiv.org/pdf/2603.26337v3#page=5)
- **2.2. Construction and validation.** Filtering by test changes and issue links left 14,333 PRs. Intent selection reduced this to 2,931, and execution checks left 580. A GPT-5.2 audit removed 52, leaving 528 instances. Agreement with manual checks was 96% over 100 decisions. The 100-task Lite subset was optimized to reproduce patch application and resolution rates for the three evaluated configurations. [PDF, p. 4](https://arxiv.org/pdf/2603.26337v3#page=4) [PDF, p. 5](https://arxiv.org/pdf/2603.26337v3#page=5)
- **2.3–3, Figure 2 and Table 1.** The normalized traces are supplemented with information recovered from the applied patch. The metrics distinguish coverage of reference elements from the proportion of additional predicted elements. DeepSeek assessed semantic matches. After reconciliation, the human assessments agreed with the automated judgment in 97/100 checked cases. Each agent–task pair had one run. [PDF, p. 5](https://arxiv.org/pdf/2603.26337v3#page=5) [PDF, p. 6](https://arxiv.org/pdf/2603.26337v3#page=6) [PDF, p. 7](https://arxiv.org/pdf/2603.26337v3#page=7)
- **4, Tables 2–4.** With DeepSeek V3.2 on the full set of 528 tasks, AutoCodeRover implemented 152 features, TraeAgent 278, and mini-SWE-Agent 370. More patches applied successfully (508, 417, and 506, respectively). Table 3 compares agreement with the reference after excluding patch application failures. Changing the base model in the Lite experiment in Table 4 moves mini-SWE-Agent from 71% to 79% and TraeAgent from 52% to 77%. - **5. Discussion and limitations.** GPT-5.5 rated the visible tests insufficient in 29/528 cases. Manual review of 100 instances found six tasks and two steps implied by the input but omitted from the reference. Of 127 successful implementations without an exact match, the evaluator classified 89 as reasonable alternatives. An extra localization phase in TraeAgent solved four of 16 selected failures but introduced regressions among ten rechecked successes. The GPT-5.5 judgments received no separate human validation. ## Independent verification

Table 3 compares runs that passed or failed testing after successful application, across files, tasks and steps for three agents. The audit calculated the relative change from successful runs for each of the nine pairs and gave each pair equal weight. The resulting means, −35.67% for coverage and +94.06% for excess predictions, reproduce the abstract. Taking ratios of the means of the same cells would give −33.28% and +67.96%.
