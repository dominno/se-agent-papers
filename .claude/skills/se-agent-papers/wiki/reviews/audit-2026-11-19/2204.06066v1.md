# Finding and Analyzing Crash-Consistency Bugs in Persistent-Memory File Systems

Audit opened on 19 November 2026 for version `2204.06066v1`, 16 pages. [Paper record](../../sources/arxiv-2204.06066.md) · [arXiv record](https://arxiv.org/abs/2204.06066v1) · [Authors, license and checksum](../../raw/metadata/2204.06066.metadata.json)

## Sections and evidence

- §§1–2. Persistent-memory file systems persist changes at a different granularity from block devices. The study examines crash correctness and reconstruction of volatile structures. It distinguishes atomicity violations, data loss and failure to remount the file system. [PDF, p. 1](https://arxiv.org/pdf/2204.06066v1#page=1) [PDF, p. 2](https://arxiv.org/pdf/2204.06066v1#page=2) [PDF, p. 3](https://arxiv.org/pdf/2204.06066v1#page=3)
- §3 and Figures 1–2. FlyTrap records persistence events and compares the recovered state with a permissible system state. ACE and Syzkaller provide two different distributions of test operations. The study omits some combinations and assumes that flushing a cache line is atomic. These choices limit which faults the tests can detect and prevent the results from establishing correctness. [PDF, p. 4](https://arxiv.org/pdf/2204.06066v1#page=4) [PDF, p. 5](https://arxiv.org/pdf/2204.06066v1#page=5) [PDF, p. 6](https://arxiv.org/pdf/2204.06066v1#page=6) [PDF, p. 7](https://arxiv.org/pdf/2204.06066v1#page=7)
- Section 4, Figure 3 and Tables 1–2. ACE found 15 of 18 distinct bugs across four systems in less than three CPU hours in total. Table 1 counts associations with calls, and a bug can affect several calls. Table 2 assigns two identifiers apiece to two bugs shared by PMFS and its derivative WineFS. The authors separately report eight bugs that also occur without a crash. [PDF, p. 8](https://arxiv.org/pdf/2204.06066v1#page=8) [PDF, p. 9](https://arxiv.org/pdf/2204.06066v1#page=9) [PDF, p. 10](https://arxiv.org/pdf/2204.06066v1#page=10)
- §§5–6 and Table 3. Fourteen of 18 bugs were classified as logic errors. Changes to the persistence mechanism affected performance in opposite directions on two microbenchmarks, highlighting the importance of the operation measured. The authors discuss the trade-off between implementation complexity and application-level guarantees. References follow the conclusions and complete the PDF. ## Independent check of the paper record
