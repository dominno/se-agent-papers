# Toolformer: Language Models Can Teach Themselves to Use Tools

Audit opened on 19 November 2026 · version `2302.04761v1`. [Paper record](../../sources/arxiv-2302.04761.md) · [arXiv record](https://arxiv.org/abs/2302.04761v1) · [Retrieval metadata](../../raw/metadata/2302.04761.metadata.json)

## Findings and evidence

- **1–3. The method and tools.** Figures 1–3 illustrate tool calls, candidate generation and filtering, and a question-answering demonstration. The model is fine-tuned on text augmented with calls that lower next-token loss relative to both controls, one with no call and one with a call but no response. Table 1 describes five text APIs. Table 2 shows how the example count depends on the threshold. - **4.1–4.2. Zero-shot tasks.** Tables 3–4 show improvements on factual queries and arithmetic. Table 5 shows lower performance than GPT-3 on all three open-domain QA datasets. In Table 6, translation improves results over the same model without tools in all six languages, although the GPT-J baseline still wins in some. Table 7 covers temporal tasks. The calendar was used for 54.8% of DATESET examples and 0.2% of TEMPLAMA examples. - **6–8. Related work and limitations.** The model learns from its own filtered proposals. The comparison methods use examples for each task. Tool calls were generated independently, the decision to call a tool ignores its cost and the decoding procedure under study permits at most one call per example. The references precede the appendices. ## Verification of the paper record

On SVAMP, enabling tools raises the Table 4 score from 6.3 to 29.4 (23.1 percentage points). Untuned GPT-J scores 5.2. In Table 8, Toolformer without tools and GPT-J fine-tuned on CCNet both have perplexities of 10.3/10.5 on WikiText/CCNet. Standard GPT-J scores 9.9/10.6. The card’s claim about retaining general language ability was narrowed to the baseline and measurements actually used. [PDF, p. 6](https://arxiv.org/pdf/2302.04761v1#page=6) [PDF, p. 8](https://arxiv.org/pdf/2302.04761v1#page=8)

An example calendar response in Appendix D calls 20 November 2020 a Sunday. An independent calculation using the Gregorian calendar gives **Friday**. This is an error in the example. It gives no basis for estimating how often similar errors occur in the evaluation dataset. [PDF, p. 17](https://arxiv.org/pdf/2302.04761v1#page=17)
