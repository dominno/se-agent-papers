# Harness-of-Harness: Multi-Day Autonomous Software Development with Continual Improvement

Audit dated 19 November 2026, version `2609.01481v1`. [Publication card](../../sources/arxiv-2609.01481.md) · [arXiv record](https://arxiv.org/abs/2609.01481v1) · [Local provenance metadata](../../raw/metadata/2609.01481.metadata.json)

## Sections and appendices

- **Sections 1–3, Figures 1–3, and Algorithm 1.** HoH uses successive calls to an existing agent for planning, implementation, and testing. Each iteration passes the project state, plan, and test evidence to the next. The development process cannot see the final score from the external benchmark. - **Section 4, Table 1, and Figures 4–6.** The main evaluation includes 45 GameCraft tasks and 15 FrontierSWE tasks, with three harness–model pairs. For Codex/GPT-5.5, the GameCraft score rises from 49.58 to 71.52, FrontierSWE Dominance from 44% to 71%, and the mean ProgramBench test pass rate from 60.41% to 66.50%. Each benchmark uses a different scale. **Independent calculation:** averaging the nine relative gains from the aggregates in Table 1 gives 52.248%, which rounds to the reported 52.25%. The largest relative gain, 82.86%, comes from Pi’s Dominance score rising from 35% to 64%. - **Tables 2–3.** Three standard Codex passes on GameCraft scored 58.24 using 6.33 million tokens. Three HoH loops scored 71.52 using 8.41 million tokens. The comparison matches round counts but allows different token budgets. Scores fell to 63.39 without plan updates, 65.23 without test feedback, and 63.67 without carrying over the latest code. ### Follow-up search for ProgramBench data, 20 November 2026

**Source file identified.** In the arXiv v1 source archive, lines 12–19 of `sections/04_experiments.tex` identify the source of Table 1 as `supplementary/data/programbench/programbench_pass_rate_by_iteration.csv`. The comment specifies `loop_1` through `loop_3` and distinguishes them from `best_of_3`. The archive omits the `supplementary/data/` directory. Its `supplementary/generated/` directory contains tables for GameCraft and FrontierSWE. The arXiv submission history lists only v1. **Recalculating the results.** The official ProgramBench registry held 31 submissions. Neither those entries nor the titles of 38 public pull requests identified an HoH evaluation. ProgramBench-Tests gives the underlying benchmark tasks and tests. It does not identify which tasks the authors selected or which tests their solutions passed. The metric averages each task’s fraction of hidden tests passed. The project page and Table 1 therefore support checking the reported Vanilla-to-HoH@3 differences of +6.09 percentage points for Codex, +12.29 for OpenCode, and +16.85 for Pi. Independent verification of any of the 12 aggregate scores (three models by four conditions) requires the task-level results. **Material needed from the authors.** Obtain the v1 `programbench_pass_rate_by_iteration.csv`. If it contains only aggregates, the audit also needs a manifest of evaluated task IDs with the benchmark revision, and evaluator records for each task. Sufficient fields are model configuration, condition (Vanilla or HoH@1–3), number of tests passed, number counted, and the rule for missing or failed runs. Per-task `eval.json` files with test metadata, following the ProgramBench submission specification, are an equivalent source. The repository provides contact information for the authors.
