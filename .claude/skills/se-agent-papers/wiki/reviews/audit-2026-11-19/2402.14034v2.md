## Sections 1–3. Architecture and interface

Actors controlled by a model or a user communicate through messages. The architecture diagram distinguishes the agent, service and model layers. A pipeline specifies the order of actions, and MsgHub broadcasts messages within a group. Table 1 lists the built-in classes. Examples and screenshots illustrate the user interface, monitoring, the DAG-based workstation and prompt tuning. ## Sections 4–8. What the Mechanisms Do

The authors distinguish errors handled by the program, errors that a model can help resolve and errors requiring intervention. An expired key illustrates the limits of automatic recovery. Multimodal data are stored separately from messages. The tool module separates prompt preparation, action selection and execution. The RAG configuration keeps knowledge separate from agent configuration. The distributed layer connects local and remote agents while retaining a procedurally defined control flow. ## Sections 9–11 and Appendices

The eight applications cover dialogue, group chat with addressed messages, the Werewolf game, distributed deployment, a RAG copilot, search, SQL queries and the visual Workstation. Code examples document the interface. Appendix A contains a dialogue transcript. Appendix B traces private and public roles and the final vote, which eliminates Player2 and gives the village the win.
