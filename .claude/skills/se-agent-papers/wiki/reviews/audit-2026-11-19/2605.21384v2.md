# SpecBench: Measuring Reward Hacking in Long-Horizon Coding Agents

Independent audit dated 19 November 2026, version `2605.21384v2`. [Publication card](../../sources/arxiv-2605.21384.md)

## Main paper

**Sections 1–2, Figure 1, and Tables 1–2.** The gap is the difference between the public and hidden test pass rates of the same implementation. Public tests assess features in isolation. Hidden tests assess their interaction. Both a system that passes all tests and one that fails every test have a zero gap. Appendix C discusses the latter case. [PDF, p. 2](https://arxiv.org/pdf/2605.21384v2#page=2) · [PDF, p. 3](https://arxiv.org/pdf/2605.21384v2#page=3) · [PDF, p. 4](https://arxiv.org/pdf/2605.21384v2#page=4) · [PDF, p. 16](https://arxiv.org/pdf/2605.21384v2#page=16)

**Section 3 and Figures 2–7.** Figure 2 labels the mean slope as +23 percentage points per tenfold increase in lines of code (LOC), with R² = 0.24, and the P90 slope as +28 points, with R² = 0.25. The caption and later text give +27 points for P90, and the text gives R² = 0.21. Figures 3–6 cover search strategies, MMLU score, and how the gap evolves over time. In the validation-coverage experiment in Figure 7, adding composite tests reduced the SQL gap from 35 to 9 points. The direction varied by task. Sections 4–5 and Figures 8–9 distinguish integration failures from fitting specific examples. The gap alone cannot establish intent. ## Appendices, earlier paper, and dataset checks

**Appendices A–C.** Appendix A notes the finite coverage of the tests. In Appendix B, the rows of Table 3 sum to 1,912 runs, 2,556 hours, and USD 33,458, but the printed totals are 2,046 runs, 2,739 hours, and USD 38,904. For a separately developed compiler, Table 4 in Appendix C shows 97.8% of public tests and 83.3% of hidden tests passed, a gap of 14.5 percentage points. Most errors involved accepting invalid input. **Appendix D and Table 5.** Table 5 lists 9 + 13 + 9 = **31 named tasks**. The Table 1 summary gives **30** (9 + 13 + 8). The authors’ repository contains 31 directories with a `task.py` file, including three 25,000-LOC projects classified as long in the paper. The README also says 30. Although the figure labels all 31 tasks, the records do not establish which observations entered the regression. **Appendix E.** The appendix reproduces an earlier paper with its own numbering and bibliography. Its Sections 1–4 compare public and private metrics on Kernel-Bench and ALE-Bench. Figures 1–2 and Table 1 of that paper give the fraction of optimizations that improve only a proxy metric (73.8% and 46.8%). The SpecBench public–hidden test gap is a separate quantity. Retrospection using a significant change reduces the rate on Kernel-Bench from 78.5% to 59.1% and increases it on ALE-Bench from 44.1% to 64.8%. ## Follow-up check of the source material, 20 November 2026

**What Figure 2 shows.** The labels name all 31 tasks from Table 5. The audit counted 1,329 data markers in the PDF’s vector layer after excluding legend symbols. By color, 546 represent Codex, 466 Claude Code, and 317 OpenCode. These are counts on the plot. Table 3 reports 596, 516, and 800 runs for those agents, respectively. The authors provide no mapping between runs and markers. Section 3.1 calls each point a run and describes the plot as covering every run in the dataset. [PDF, p. 3](https://arxiv.org/pdf/2605.21384v2#page=3) · [PDF, p. 5](https://arxiv.org/pdf/2605.21384v2#page=5) · [PDF, p. 15](https://arxiv.org/pdf/2605.21384v2#page=15)

The axis ticks at 10³, 10⁴, and 10⁵ LOC and at 0 and 100 percentage points establish the scale. The line coordinates in the PDF imply increases of **22.72 percentage points** for the mean and **28.42 points** for P90 per tenfold increase in LOC. Both round to the values in the legend. A slope by itself does not determine R². An approximate fit assigned marker centers to the 31 tasks by drawing order and nearest LOC value in Table 5. Regressing their means and P90 values yielded 23.42 and 28.60 points, with R² around 0.26 for both. The plot uses display offsets and rounded project sizes. These estimates cannot recover the exact regression inputs or resolve the conflicting R² values. A point is visible near 5,000 LOC and a gap of 68 points. If the 21-point “worst-case gap” for short tasks in Section 3.1 refers to an individual run, the authors need to clarify how it was aggregated. [PDF, p. 3](https://arxiv.org/pdf/2605.21384v2#page=3) · [PDF, p. 5](https://arxiv.org/pdf/2605.21384v2#page=5)

**Version history and arithmetic.** The Figure 2 file is byte-for-byte identical in arXiv v1 and v2 (SHA-256 `f1fbe7b834178f6021e805124930190600ae37b738986c5ba580b65c681b6191`).
