# AgentCoder: Multi-Agent-based Code Generation with Iterative Testing and Optimisation

Audit opened on 19 November 2026 · version `2312.13010v3`. [Paper record](../../sources/arxiv-2312.13010.md) · [arXiv record](https://arxiv.org/abs/2312.13010v3) · [Retrieval metadata](../../raw/metadata/2312.13010.metadata.json)

## Section review

- Sections 1–2. The v3 identifier on the title page confirms the paper version despite the difference between its title and the arXiv record. The authors examine how a generator’s mistakes affect tests produced by the same agent. They discuss code models, prompting techniques and agent collaboration. [PDF, p. 1](https://arxiv.org/pdf/2312.13010v3#page=1) [PDF, p. 2](https://arxiv.org/pdf/2312.13010v3#page=2) [PDF, p. 3](https://arxiv.org/pdf/2312.13010v3#page=3)
- Sections 3.1–3.3 and Figure 1. The programmer and test designer receive the same specification and work independently. A local script executes the tests. Page 2 attributes test design to the executor. The method instructions and appendix script clarify the roles. [PDF, p. 2](https://arxiv.org/pdf/2312.13010v3#page=2) [PDF, p. 4](https://arxiv.org/pdf/2312.13010v3#page=4) [PDF, p. 5](https://arxiv.org/pdf/2312.13010v3#page=5) [PDF, p. 22](https://arxiv.org/pdf/2312.13010v3#page=22)
- Sections 4.1–4.2 and Table 1. The evaluation covers five base models and four datasets, two of which have expanded test suites. Some baseline results come from the corresponding publications. GPT-4 achieves pass@1 of 96.3%, 86.0%, 91.8% and 91.8% across the four datasets. The four cells average 91.475%. Relative to the reported zero-shot mean of 59.7%, the gain is about 31.8 percentage points, or 53.3% relative. The “32.7%” on page 7 does not match this calculation. [PDF, p. 6](https://arxiv.org/pdf/2312.13010v3#page=6) [PDF, p. 7](https://arxiv.org/pdf/2312.13010v3#page=7)
- Sections 4.3–4.5 and Tables 2–4. On HumanEval with GPT-3.5-turbo, the programmer alone scores 61.0%, the programmer with the test designer 64.0%, the programmer with the executor 64.6% and the full system 79.9%. The full system improves from 74.4% in the first iteration to 79.9% in the fifth. The authors assess test accuracy against the reference solution. The GPT-4 row of Table 4 reports 89.6% and 91.4%. [PDF, p. 7](https://arxiv.org/pdf/2312.13010v3#page=7) [PDF, p. 8](https://arxiv.org/pdf/2312.13010v3#page=8)
- Sections 4.6–4.7 and Tables 5–8. GPT-4 achieves line coverage of 91.7% and 92.3% on reference solutions. Compared with a shared conversation, two separate conversations improve test accuracy (Table 6), program pass@1 (Table 7) and line coverage (Table 8). Line coverage measures which lines execute. A separate check is needed to establish whether the assertions are correct. [PDF, p. 9](https://arxiv.org/pdf/2312.13010v3#page=9)
- Section 5 and Appendix A.2, Table 9. The conclusion reports pass@1 of 90.2% and 78.9% for SelfCollaboration but assigns it token costs of 138.2 thousand and 206.5 thousand, which belong to MetaGPT. SelfCollaboration’s actual **response** tokens were 74.3 thousand and 89.2 thousand. AgentCoder used 56.9 thousand and 66.3 thousand response tokens. These counts exclude input tokens. Section 5 refers readers to a discussion of limitations and broader impacts. Neither the appendix contents list nor sections A.1–A.6 contain that discussion. The references occupy pages 10–13. - Appendices A.1 and A.3–A.6, Figures 2–12. The response format lets the executor extract code blocks. Two examples give code and tests for numerical proximity and monotonicity. A counterexample to Figure 2 uses the numbers 0 and 1 with a threshold of 1. The condition in Figure 2 returns true at equality even though the task specifies a strict inequality. Figure 1 uses the strict inequality. Figures 6–10 show messages, responses and the test script. In A.5–A.6 the text reverses the numbers of Figures 11 and 12 relative to their captions. The public repository contains the code, prompts and data.
