# Using Process Mining to Generate AI Agents from Software Engineering Process Records

**Paper:** [2607.04948](https://arxiv.org/abs/2607.04948) · [PDF](https://arxiv.org/pdf/2607.04948) · [HTML](https://arxiv.org/html/2607.04948)  
**Review status:** `fulltext_reviewed` · **Full text reviewed:** **yes**

## Research findings

**Method.** The authors combine three forms of process mining to derive agent roles and specifications from project event logs, reflecting the local division of work. [PDF, p. 1](https://arxiv.org/pdf/2607.04948v1#page=1)

**Key result.** Ten participants evaluated written specifications for four roles. On a 1–5 scale, median ratings were 4 for operational clarity, 3 for the ability to attribute responsibility for an error and 2 for clarity of autonomy boundaries. Three functional tests separately evaluated routing effectiveness. [PDF, p. 11](https://arxiv.org/pdf/2607.04948v1#page=11) [PDF, p. 12](https://arxiv.org/pdf/2607.04948v1#page=12) [PDF, p. 14](https://arxiv.org/pdf/2607.04948v1#page=14)

**Limitations and scope.** Participants assessed the written specification. Agreement with user expectations does not measure how well a deployed agent performs. [PDF, p. 15](https://arxiv.org/pdf/2607.04948v1#page=15)

## Overview

The authors use process mining on software-development logs to identify roles and design agents that reflect actual work. [PDF, p. 1](https://arxiv.org/pdf/2607.04948v1#page=1)
