# Do Automatic Test Generation Tools Generate Flaky Tests?

**Paper:** [2310.05223](https://arxiv.org/abs/2310.05223) · [PDF](https://arxiv.org/pdf/2310.05223) · [HTML](https://arxiv.org/html/2310.05223)  
**Review status:** `fulltext_reviewed` · **Full text reviewed:** **yes**

## Research findings

**Method.** For 1,902 Java and 4,454 Python projects, the authors compared developer-written tests with tests generated by EvoSuite and Pynguin. They ran the tests 100 times in fixed and random order. [PDF, p. 3](https://arxiv.org/pdf/2310.05223v1#page=3) [PDF, p. 4](https://arxiv.org/pdf/2310.05223v1#page=4)

**Key result.** Without flakiness suppression, EvoSuite generated 3,832 flaky tests out of 264,000, versus 1,285 out of 310,193 with suppression. The reported 71.7% is a relative decrease in the rate calculated from the rounded values 1.45% and 0.41%. The counts give a 71.46% decrease in the rate and a 66.47% decrease in the number of flaky tests. [PDF, p. 7](https://arxiv.org/pdf/2310.05223v1#page=7)

**Limitations and scope.** Two hundred runs may miss rare failures. The root-cause analysis covers a sample of 481 order-independent flaky tests. [PDF, p. 6](https://arxiv.org/pdf/2310.05223v1#page=6)

## Overview

The study examines flaky behavior in automatically generated tests, including sensitivity to the environment and test execution order. [PDF, p. 1](https://arxiv.org/pdf/2310.05223v1#page=1)
